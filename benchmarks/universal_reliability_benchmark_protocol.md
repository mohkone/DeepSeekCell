# Universal Reliability Benchmark Protocol

This protocol evaluates whether a frozen Risk-k reliability model transfers
across annotation backends and model families. It does not define a new
selector, retrain Risk-k, tune thresholds, or make additional LLM calls.

## Scientific Question

```text
Can a reliability model trained once predict which annotations need refinement
across different annotation models?
```

This reframes DeepSeekCell from a DeepSeek-specific pipeline into a reusable
reliability layer for LLM-assisted single-cell annotation.

## Locked Design

1. Train Risk-k once on the development benchmark.
2. Freeze the resulting RDS model and record its hash.
3. Evaluate the same frozen model on all compatible annotation outputs.
4. Do not retrain, recalibrate, retune, or change the feature set for each
   target model.

Compatible annotation outputs must contain the paired debug/provenance columns
used by the reliability framework, including first-pass predictions, truth
labels, confidence values, evidence flags, cluster identifiers, backend/model
identifiers, and, when selector correction efficiency is evaluated,
FullRefined outcomes.

## Command

```bash
Rscript benchmarks/analyse_universal_reliability_transfer.R \
  results/benchmark_debug \
  results/reliability_model_v1.1_error.rds \
  results/universal_reliability_transfer \
  deepseek-chat
```

Optional fixed-budget controls:

```bash
set DEEPSEEKCELL_UNIVERSAL_BUDGET_FRACTION=0.2
set DEEPSEEKCELL_UNIVERSAL_BUDGET_MIN=1
```

An explicit integer fifth argument overrides the fractional budget.

## Primary Outputs

The script writes:

```text
*_features.csv
*_risk_transfer_metrics.csv
*_risk_calibration_bins.csv
*_selector_behavior_by_block.csv
*_selector_summary_by_model.csv
*_selected_clusters.csv
*_selector_overlap_by_model.csv
*_auroc_transfer_heatmap.pdf
*_risk_calibration_by_model.pdf
*_selector_efficiency_by_model.pdf
*_selector_overlap_by_model.pdf
```

## Metrics

Risk prediction transfer:

- AUROC for first-pass error prediction.
- Brier score.
- Binary correctness negative log-likelihood.
- Expected calibration error.
- Calibration intercept and slope.
- Degradation relative to the source model.

Fixed-budget selector behavior:

- Selection precision and recall for first-pass errors.
- Wrong-to-correct revisions.
- Correct-to-wrong revisions.
- Net correction efficiency.
- Recovery fraction relative to FullRefined, when available.
- Relative refinement budget.

Cross-model consistency:

- Jaccard overlap of selected clusters.
- Overlap of the smaller selected set.

## Interpretation

If the frozen Risk-k model retains high AUROC, good calibration, and useful
selector efficiency across model families, the manuscript can claim that the
reliability layer captures general properties of annotation uncertainty rather
than quirks of a single LLM.

If transfer is weak, the result remains informative: it indicates that
model-specific calibration or source-specific Risk-k models may be required.

## Scope

The first implementation targets LLM-style debug outputs generated by the
paired benchmark. Deterministic annotation methods can be evaluated by this
protocol once they emit the same reliability-feature table with evidence,
confidence, prediction, truth, and provenance columns.
